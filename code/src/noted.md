# 合成负样本流水线 —— 方法记录(给论文手)

对应代码:`syn_neg_rules.py`(选块+拼图)、`syn_neg_screen.py`(二次筛选)、
`solve_q1_realneg_check.py`(拼接伪影验证实验,见 4.3)。
这份文档记录用了什么方法、为什么这么设计、踩过哪些坑、目前还有哪些没解决的
已知局限——写方法部分和局限性讨论时可以直接摘。

## 1. 背景:为什么需要合成负样本

问题1(分类:图像是否存在残损)被约化成基于问题2(检测)的判定:对图像跑
检测模型,若最高置信度低于阈值 τ,判定为"无残损"。这个约化是否成立,取决于
"真正无残损的图像上,检测模型输出的置信度确实普遍低于 τ"——需要一批**确定
不含任何残损**的图像去验证。数据集里没有现成的"纯干净"整图(残损图占比高,
且没有纯负样本子集),所以从残损图里挖不含残损的局部区域(clean cell),
拼接成合成负样本,分 `tune`(调 τ)和 `eval`(评估约化假设是否成立)两批。

## 2. 选块规则(`syn_neg_rules.py`)

### 2.1 标注框排除(AABB + margin)

YOLO 格式标注(归一化 `class x_center y_center w h`)转像素坐标后,按
`margin=12px` 外扩,再用 `cell=320`、`step=160` 的滑动窗口扫描整图,窗口与
任意一个外扩框有重叠就淘汰。外扩是为了避开标注框边缘可能残留的、没被框完整
框住的残损像素。

只在 `images/train`(3300 张)里选块,`test`(413 张,官方最终验证集)完全
不碰——避免验证集信息泄漏到训练/调参环节。

### 2.2 一级过滤:整体方差(`check_patch`)

`VAR_THRESH = 200`,patch 内全部像素的方差低于此值判定为纯色/天空一类的
低信息量区域,丢弃。能抓住"整块都很平"的情况(天空、大面积纯色反光面),
抓不住"局部有问题、局部正常"混在一起的情况——两种内容混合后整体方差不高
不低,能骗过这个阈值。

### 2.3 二级过滤:局部打码块检测(`detect_blank_block`)

**要解决的问题**:一级过滤漏掉的典型案例是数据集里少量图像存在人工打码/
遮挡的白色矩形块(例如 `2380.jpg`),块本身内部平滑无纹理,但周围是正常
集装箱纹理,混合后整体方差不足以触发一级过滤。

**第一版尝试(已废弃)**:用 Canny 边缘密度,边缘像素数低于固定阈值判定为
打码。问题:暗光图像本身边缘就稀疏,固定边缘阈值会把正常的低对比度纹理
(如 `2950.jpg`)也误判成打码,存在系统性假阳性。

**最终方案**:把 cell 切成 `BLANK_GRID=8` × 8 的网格,每个小格子单独算局部
方差,方差低于 `FLAT_VAR_THRESH=1.0` 判定为"无纹理小格"(自然图像的传感器
噪声/量化几乎不可能让方差精确趋近于 0,只有数字插入的纯色块会这样,这个信号
对曝光水平不敏感,不会重蹈 Canny 版本的暗光误判覆辙)。用连通域分析
(`cv2.connectedComponents`)找"无纹理小格"连成一片、且面积占比超过
`BLANK_MIN_FRAC=0.08` 的区域。

仅这一条还不够:集装箱本身的纯色喷漆面(波纹板凹槽处)局部方差也很低,会
被误判。区分办法是**连通区域贴住 cell 边界的条数**——真实喷漆平面是连续
延伸出画面外的物理表面,裁进 cell 后通常贴住多条边界;打码矩形是完整嵌在
正常纹理里的"孤岛",一般只贴住 0~1 条边。所以增加约束:贴边数
`≤ max_border_touch(=1)` 才判定为打码块。

验证:5 个已知打码案例(`2380`/`511`/`3260` 等)与 2 个已知正常喷漆面案例
(`3117.jpg` 两处波纹板裁块)构成的回归测试,7/7 通过。200 张随机抽样下
整体过滤保留率 96.9%(417 张里拒绝 13 张)。

### 2.4 拼接与可复现性

4 个 320×320 clean cell 拼成一张 640×640 合成图(2×2 网格,不做羽化融合)。
候选池打乱用固定 `SEED=42`,因此任意一张输出图对应的 4 个源 `(stem, x, y)`
可以精确复现——排查具体某张合成图里的问题时,重新走一遍
`get_all_cells → flatten_cells → random.seed(42) → shuffle` 就能定位到
问题究竟来自哪张源图的哪个位置,不需要额外记录元数据(`syn_neg_screen.py`
里 `rebuild_index_mapping` 用的就是这个技巧)。

**当前规模**:1882 张源图有可用 clean cell,共 6701 个候选 cell,支持最多
1675 张 640×640 合成图;当前生成 1000 张(tune 500 / eval 500,互不重复)。

## 3. 二次筛选(`syn_neg_screen.py`)

一级+二级过滤之后,人工抽查仍发现两类漏网样本(见第 4 节)。为了把 1000 张
的人工审查工作量按优先级排序,加了一层不依赖检测模型的二次筛选。

### 3.1 为什么不能用检测模型自己筛(重要:方法论层面的坑)

最初想到的方案是:拿正在训练的 YOLO 检测器(`solve_q2.py`)跑一遍这批合成
负样本,凡是给出较高置信度的直接标记为可疑。**这个方案被否决**——`tune`/
`eval` 存在的目的就是拿检测模型去测"它在确定无残损的图上会不会误触发",
用来验证约化假设、给 τ 调参。如果筛选时已经用同一个模型把它会触发的样本都
剔除掉,剩下的自然全是模型不会触发的样本,measured FPR 会被人为做低——
这个 eval 从设计上就失去了检验模型的意义,而且会把"模型自身的检测盲区"
系统性地藏进"已确认干净"的负样本集里,这恰恰是最不该发生的事。

结论:tune/eval 的筛选必须用跟被评估对象(检测模型)完全独立的信号,不能
用模型自己来筛自己要被拿来测的数据。

### 3.2 方案2:HSV 天空启发式

**要解决的问题**:方差类过滤器抓不住"大片天空 + 高对比度集装箱轮廓边缘"
的混合内容——边缘本身把整体/局部方差都拉高,骗过前面两层过滤,但本质上
这个 cell 大部分面积是背景天空,不是集装箱材质,不该作为"无残损集装箱表面"
的代表样本。

**第一版实现(有缺陷)**:HSV 空间里,饱和度低(`S < 60`)且亮度高
(`V > 140`)的连通像素区域占比作为"天空占比"。用连通域而不是像素总占比,
是为了避免"画面里散落几个反光高光点"被误算成大片天空。

**发现的问题**:这个纯颜色条件对"浅色调、反光发白/发粉的集装箱波纹板"
同样成立——实测把一块正常的浅色波纹板判成天空占比 0.501(≥ 高危阈值)。
1000 张实跑下,一级高危有 391 张,占比明显偏高,人工抽查确认是系统性误判。

**修复**:真天空和误判波纹板的色相(Hue)分布截然不同——天空集中在蓝青调
(实测已知天空案例 `181.jpg@(0,0)` 色相中位数 105),误判波纹板集中在
品红/粉调(实测 `2423.jpg@(320,320)` 色相中位数 152)。加一条色相范围限制
(`SKY_HUE_LOW=85` ~ `SKY_HUE_HIGH=140`),饱和度接近零(`< 15`,过曝或阴天
的近白色,色相本身没有意义)时不卡这条,豁免。

修复前后对照(同一批已知案例):

| 案例 | 修复前 sky_frac | 修复后 sky_frac | 判定 |
|---|---|---|---|
| `181.jpg@(0,0)` 真天空(应抓住) | 0.375 | 0.194 | 仍高于中危阈值 0.15,正确保留 |
| `2423.jpg@(320,320)` 误判波纹板(应放过) | 0.501 | 0.066 | 降到低危,误判消除 |
| `1690.jpg@(0,0)` 纯天空/过曝(已知案例) | — | 1.000 | 满分,无回归 |

修复后全量重跑:高危 391→225 张。

### 3.3 方案3:源图黑名单(降级方案,未能自动化)

**最初设想**:自动识别"多集装箱堆叠 + 可能有水印"的库存图类源图(这类图
标注不全的风险显著更高,见第 4.2 节),而不是逐张人工翻。

**测试过的判据,均在真实数据上验证失败**:

1. 分辨率/宽高比异常——`dataset_3713` 全部图片统一 resize 到 640×640,
   这个维度上的信息在预处理阶段就被抹掉了,完全没有区分度。
2. 全局颜色统计(HSV 均值)异常——已知问题源图(`2905`/`511`/`3260`)的
   色相/饱和度/亮度均值,和随机抽取的正常图相比没有可用的分界线。
3. 边框像素方差(letterbox 填充检测)——已知问题源图的边框方差
   (735~4399)完全落在正常样本的方差区间(472~8696)内,无区分度。
4. 水印周期性检测(FFT,屏蔽中心低频后看环状高频区域的峰值/均值比)——
   已知问题源图(2905,比值 1.80)落在正常样本区间(1.43~1.99)正中间,
   没有分离。水印本身透明度低、覆盖面积小,不足以在全图尺度的频域上
   形成可检测的强周期峰。

**结论**:这类"图里到底有几个集装箱、标注全不全"的判断,本质是语义/内容
理解问题,普通图像统计特征摸不到,没有勉强凑一个不可靠的阈值。改成人工
维护的黑名单(`SOURCE_BLOCKLIST`),已确认有问题的源图 stem 记录在案,
拼图只要用到黑名单里的 stem,直接判最高怀疑级——不追求自动召回,只保证
已发现的问题不会重复出现在"低危"区。

目前黑名单:`2905`(见 4.1)、`284`(见 4.2)。**这两个都是人工抽查偶然
翻到的,不代表已经找全**——如果水印检测后续想再啃,方向是针对具体水印
样式(如 dreamstime 的半透明圆形 logo + 对角重复文字)做局部模板/关键点
匹配,而不是全局频域统计,前者信号更局部、更适合这种低透明度覆盖的情况。

### 3.4 方案4:三级怀疑分归档

不区分 tune/eval,1000 张放一个池子里统一筛,按以下规则分三级,复制(不
移动原图)到 `code/data/syn_neg_screen/{tier1_high,tier2_mid,tier3_low}/`,
文件名 `{score:.3f}_{原始编号:04d}.jpg`(分数打头,方便按怀疑度排序审查):

- **tier1_high**(高危,`score ≥ 0.5` 或命中源图黑名单):黑名单命中固定
  `score=1.0`;天空占比 `≥ TIER1_SKY_FRAC(0.5)` 直接判定,大概率整块基本
  是天空/大面积异常。
- **tier2_mid**(中危,`0.15 ≤ score < 0.5`):中等天空占比,人工优先看。
- **tier3_low**(低危,`score < 0.15`):自动规则判定基本正常。

当前(修复色相 bug + 补黑名单 284 之后)分布:tier1 225 张、tier2 386 张、
tier3 389 张。`manifest.csv` 记录每张图的原始编号、路径、分级、分数、
判定原因(`source_blocklist` / `sky_frac_high` / `sky_frac_mid` / `clean`)、
以及组成它的 4 个 `(源图stem, x, y)`,供后续追溯排查用。

## 4. 已发现但未被现有规则自动兜住的问题案例

### 4.1 未标注残损污染(`2905.jpg`,已加入黑名单)

`2905.jpg`:旋转过的、带 `tradetime.com` 水印的库存图,画面里至少两个
集装箱有明显残损,`2905.txt` 只标注了其中一个(Hole)。用这张图选出的
clean cell,理论上应该避开了那个**被标注的**残损框,但另一个**完全没被
标注**的残损区域,选块算法无法识别(它只避开标注框,不理解"这里其实也有
残损")——结果是合成负样本 `syn_neg_0400.jpg` 里混进了一块真实的、肉眼
明显可见的集装箱挤压破损。

这类问题**理论上不可能被任何基于方差/颜色/纹理的过滤器自动发现**——真实
残损区域的纹理特征和正常集装箱材质并无本质差异(不像打码块那样"平滑",
也不像天空那样"颜色异常"),区分它需要语义级的残损识别能力,而这正是
问题1/2 本身要解决的任务,不可能反过来用来清洗为验证该任务而生成的数据
(见 3.1 的循环论证问题)。

### 4.2 竞赛规则导致的结构性标注不全(`284.jpg`,已加入黑名单)

`284.jpg`:dreamstime.com 水印库存图,前景一个集装箱有明显破洞,背景是
几十个集装箱堆叠成的大墙面。抽查 `syn_neg_screen` 的 tier3(低危)分组时
偶然翻到,已加入黑名单。

**这个案例比 2905 更值得写进论文的局限性讨论**:题目原文(`problem_D.txt`)
明确写道"验证集中每张图片集装箱的破损按照严重程度从大到小最多取4个"——
也就是说,标注数量本身存在竞赛规则设定的**硬上限**。对于背景里堆了几十个
集装箱的复杂场景,即便背景中确实存在未达到"前4严重"排名的真实残损,按
规则也**不会被标注**。这不是标注失误或疏漏,而是数据集标注协议本身决定的
结构性盲区——理论上讲,任何"画面复杂度高、可能包含多处残损"的图像都有
这个风险,水印库存图只是其中最容易被人工一眼识别出来的一个子类(背景元素
密度异常高、明显不是同一批监控摄像头拍摄的风格)。

**对约化假设(第1节)的影响**:这类源图产出的 clean cell,如果背景堆叠区域
恰好落在被选中的窗口内且真的存在未标注残损,会跟 `2905.jpg` 一样污染
"确定无残损"这个假设的前提。目前唯一的应对手段是黑名单(人工发现一个
加一个),没有自动化兜底,论文里如实报告这个局限即可,不需要假装已经解决。

### 4.3 拼接结构本身就是可被利用的伪影(问题3三家对比实验发现,比 4.1/4.2 更根本)

4.1/4.2 讨论的是"clean cell 内容本身混入了未标注残损",这一节是完全不同、
更根本的另一个问题:**就算每个 clean cell 内容都真的干净,把 4 个 cell 硬拼
成 2×2 网格(2.4 节,不做羽化融合)这个拼接动作本身,就会留下真实照片里
不会出现的结构性痕迹**——网格中线两侧颜色/光照/纹理硬性断层,以及旋转裁剪
留下的黑色三角形留白。这些痕迹和"有没有残损"毫无关系,但足够显眼,是可以
被分类器直接利用的捷径信号。

**发现契机**:`solve_q1.py`(检测归约)、`solve_q1_svm.py`(HOG+LBP+HSV+GLCM
手工特征 + SVM)、`solve_q1_cnn.py`(部分微调 ResNet18)三家方法在同一份评估集
(官方验证集正样本 413 张 + 合成负样本 eval 半区)上对比,AUC 随模型容量单调
递增、逼近满分:

| 方法 | AUC(合成拼接负样本) |
|---|---|
| 检测归约 | 0.8435 |
| SVM(手工特征) | 0.9951 |
| CNN(ResNet18 部分微调) | 0.9999 |

CNN 在 813 张评估图上 AUC=0.9999 意味着几乎零分类误差,这在"图像级残损识别"
这个任务难度上是不合常理的,尤其是三家方法的分数排序跟"模型能利用多复杂的
全局统计信号"这个能力排序严格一致(检测归约只看局部框 < 手工特征能抓边缘/
纹理的全局分布 < CNN 端到端能学任意全局模式),这正是 shortcut learning 的
典型指纹。

**肉眼验证**:抽查评估集里的合成负样本(如 `syn_neg_eval/syn_neg_0500.jpg`
`syn_neg_0504.jpg` `syn_neg_0507.jpg`),4 格画面经常来自颜色、光照、集装箱
型号完全不同的源图,拼接线是笔直硬边,部分格子还带旋转裁剪留下的黑色三角形
——这种"网格硬缝 + 异色块拼贴 + 黑色三角"的几何结构,在单张连续拍摄的真实
照片(不管是正样本还是任何真实负样本)里不会自然出现,不需要理解"残损"就能
把它和真实照片区分开。

**验证实验**:从 Wikimedia Commons(`Category:Shipping containers` +
`Category:Intermodal containers`,161 张候选)下载真实集装箱照片,人工筛掉
明显残损/明显不是集装箱表面/人物过多等噪声后剩 43 张单张连续照片(不拼接),
替换掉合成负样本(正样本仍用官方验证集 413 张不变),复用三家已训练好的
权重(不重新训练/调参,τ* 直接沿用各自训练时选定的值),重跑一遍评估
(`solve_q1_realneg_check.py`,结果存 `code/data/q1_realneg_check_result.pkl`):

| 方法 | AUC(合成拼接负样本) | AUC(真实非拼接负样本,N=43) |
|---|---|---|
| 检测归约 | 0.8435 | 0.8066(基本稳,-0.04) |
| SVM(手工特征) | 0.9951 | 0.7534(崩,-0.24) |
| CNN(ResNet18) | 0.9999 | **0.6701**(崩得最狠,-0.33,已接近瞎猜) |

三家在两种负样本口径下的排序**完全反了**(拼接口径:CNN>SVM>检测归约;真实
口径:检测归约>SVM>CNN)。检测归约在合成拼接负样本上分数最低,恰恰是因为它
的判定逻辑(局部残损形状候选框的最高置信度)天然不会被全局拼接结构污染,
换到真实分布反而最稳;SVM/CNN 在合成负样本上的高分,大部分是在测"认拼接缝"
的能力,不是"认残损"的能力。

**注意**:Acc/Precision/Recall/F1 在两种口径下看起来差别不大(SVM/CNN 仍有
0.90+/0.95),这是因为真实负样本验证集只有 43 张(远小于 413 张正样本),
固定阈值下少量假阳性不太拖累这几个指标——AUC(阈值无关、纯排序能力)才是
真正戳穿问题的指标,写论文/做结论时应以 AUC 为准,不要被 Acc/F1 的表面稳定
误导。

**对约化假设(第1节)的影响,以及和 4.1/4.2 的关系**:4.1/4.2 污染的是"内容
语义"(clean cell 里混入了真实残损),这里污染的是"结构统计"(拼接动作本身
制造了非语义的可分性)——两者是独立的问题,4.1/4.2 修好了也不会影响这里的
结论。三者共同说明:用合成负样本代替真实负样本去验证/训练/评估,存在多条
独立的偏差来源,现有规则(方差/HSV/黑名单)一条都堵不住这一条。

**对论文写作的建议**(留给论文手拍板,不在此文档里替论文手做决定):
1. 问题3"对比实验"如实报告两组数字(合成负样本口径 + 真实负样本抽查口径),
   不要只报合成口径下"CNN 最优"的结论——那个结论方向是错的。
2. 检测归约方法在两种口径下的相对稳健性,本身可以作为"该方法泛化性更好"的
   正面论据写进讨论,而不只是"分数较低"的弱项。
3. 真实负样本集(N=43)取景/尺度跟训练分布不完全匹配(多为集装箱堆场中/远景
   照片,不是训练集里贴近表面的特写),只做方向性诊断用,不建议当正式基准
   数字使用(样本量也偏小),这一局限应如实注明。

**如果以后想真正修**(不是必须,取决于时间预算):在 `syn_neg_rules.py` 的
拼接步骤(2.4 节)对网格接缝做羽化混合(如 `cv2.seamlessClone` 或简单的
线性渐变过渡带),消除硬边缝隙这个最明显的伪影信号,理论上能让 SVM/CNN 的
合成口径分数往真实口径靠拢,但黑色三角形留白(旋转裁剪导致)和"4 个来源
完全不同的画面拼一起"这个更本质的分布差异依然存在,羽化只能缓解不能根治,
性价比需要权衡。
