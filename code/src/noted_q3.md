## 1. 设计:逐项累加,而不是留一法(leave-one-out)

FILL_CHECKLIST 要求"自基准配置起依次加入":类别加权 → P2 头 → 1280 输入 → 强
增强,每步只变一个变量,而不是"从满配置里依次去掉一项"。两者哲学不同——
逐项累加回答的是"按现在的设计顺序,每一步实际带来多少增量",不是"每个模块
单独的边际贡献"(留一法才是后者,且需要 2×n 次训练,时间预算不允许)。

Step4(+强增强,即满配置)**复用**了此前 `explore_q3_s_res.py` 已经跑过的
`explore_s_b2_i1280_e30` 训练结果,而不是重新训练——它的配置(P2 头 +
cls_pw=1.0 + imgsz=1280 + 强增强)跟 `solve_q2.train_model()` 的默认参数
逐项对上,数值上就是 step4,省了一次约 2.5h 的训练。**但当时那次探索训练
只存了训练元数据,没跑官方 413 张测试集评估**,所以这次补跑了一遍
`evaluate_official()`(纯推理,不训练,几分钟),把 `eval_official` 写回同一个
pkl 文件,现在跟 step0~3 口径完全统一。

四步新训练(step0~3)+ step4 评估补跑,全部在 UTC+8 2026-08-20 04:59~07:1x
一次性跑完,GPU 全程无冲突进程,无报错。

## 3. 关键发现(写讨论/结论段可以直接用)

1. **类别加权(step0→1)没有起到预期效果,甚至轻微为负**:mAP@0.5
   0.1917→0.1909,$AP_s$ 0.0817→0.0753。cls_pw 从 0 提到 1.0 的调整幅度,
   或者 30 epoch 的训练长度,不足以体现类别不均衡缓解的收益。**如实报告
   "未观察到显著提升",不要为了叙事完整硬解释成正向结果**——这是消融实验
   本该暴露、而不是掩盖的信息。

2. **P2 检测头(step1→2)是全链条里唯一让 mAP@0.5 与 $AP_s$ 同步上升的一步**,
   涨幅也最大($AP_s$: 0.0753→0.0882,+17.1%相对涨幅)。这是支撑"P2 头
   专门针对小目标检测"这一设计动机最直接的证据,论文里如果只能重点强调
   一个模块,应该是这个。

3. **1280 输入单独加入(step2→3)时 mAP@0.5 大跌**(0.2143→0.1445,
   -32.6%),但 $AP_s$ 仍在涨(0.0882→0.0924)。原因判断:分辨率翻倍后
   模型有效感受野/计算量上升,30 epoch 不足以让它收敛到跟 640 输入相当
   的水平,拖累的主要是中大目标(该步 $AP_m$/$AP_l$ 相比 step2 同步下降,
   原始数据见 pkl 的 `per_class_metrics`),小目标反而因为分辨率提升直接
   受益,方向上符合"高分辨率对小目标更友好"的预期,只是被欠收敛的代价
   部分抵消了。**这一步的降分不代表 1280 输入设计有问题,是训练预算
   (30ep)不够,要写清楚不要被误读成"消融证明大分辨率没用"。**

4. **强数据增强(step3→4)把 mAP@0.5 拉回一部分**(0.1445→0.1828,
   +26.5%相对),$AP_s$ 也涨到全链条最高点(0.0924→0.0953)。合理解释是
   强增强在小样本/欠收敛场景下起到了类似"隐式延长有效训练"的正则化效果。
   $AP_s$ 在五步里单调递增到这里收尾,是"P2 头 + 大输入 + 强增强"三个设计
   叠加对小目标检测有效的最直接、最完整的证据链,写结论段可以直接引用
   这条单调趋势。

5. **⚠️ 极重要:这张消融表的绝对数值不能跟主结果表(`tab:q2-det` 等)对比**。
   消融表 5 步全部只跑了 30 epoch(时间预算约束),而 `solve_q2.py` 官方
   训练用的是 100 epoch。Step4(+强增强)的配置跟官方训练**完全相同**
   (P2+cls_pw=1.0+1280+强增强),但 30ep 只有 mAP@0.5=0.1828,官方
   100ep 训练(`q2_result.pkl`)同口径算出来是 **0.3623**——足足差了近
   2 倍。这不是矛盾,是训练轮数不同导致的正常现象,**但如果论文里两张表
   放在一起、读者会本能地拿数字互相对照,必须在消融表的表注或正文里明确
   写清楚"消融实验训练轮数为 30 epoch,用于比较相对增量,非最终模型
   性能"**,否则会被当成数据不一致的硬伤。

6. **类别拆开看,Rusty(class2)全程是三类里最弱的**,尤其在 step3(1280
   输入,欠收敛最严重的一步)$AP_s$ 掉到 0.0114,几乎检测不到小尺度锈蚀。
   Dent/Hole 的 $AP_s$ 在同一步都还能维持在 0.03/0.23 量级。合理怀疑
   Rusty 本身边界模糊、和正常表面材质对比度低,在小尺度、低分辨率(640)
   下更难判别——这个观察在满配置(step4)下依然成立(class2 $AP_s$=0.0149,
   全表最低),值得在讨论"类别间难度差异"或"局限性"时提一句,不是训练
   配置问题,是这个类别本身的视觉特性问题。

## 4. 复现方式

```
python code/src/ablate_q3_steps.py --step {0,1,2,3} --batch 2 --epochs 30
```
Step4 结果已经在 `q3_explore_explore_s_b2_i1280_e30.pkl` 里(含
`eval_official`),不需要重跑;真要重跑等价配置,直接用
`solve_q2.train_model(..., use_p2=True, cls_pw=1.0, strong_aug=True)` 默认
参数、把 `solve_q2.IMG_SIZE` 设成 1280 即可(参照 `explore_q3_s_res.py` 的
monkeypatch 写法)。
