# 数据概览统计 —— 方法记录(给论文手/建模手)

对应代码:`fig_data_dist.py`(左:三类实例数;右:单图实例数直方图)、
`fig_data_scale.py`(bbox 面积占比分布,对数轴)。数据源:
`code/data/dataset_3713/labels/train/*.txt`(原始 YOLO 检测格式标注,训练集
3300 张,`fig_data_dist.py`/`fig_data_scale.py` 里的统计口径全部来自训练集,
跟 `03-model-analysis.tex` 数据概览段落引用的数字一一对应)。

## 1. 已核对一致的数字

`03-model-analysis.tex` 第 10 行写的这些数字,跟脚本重新统计的结果精确匹配:
- 训练集 8038 个实例,凹陷 3934 / 破洞 946 / 锈蚀 3158
- 单图实例数 1~50,单实例图像占比 49.06%(文字写"近半数")
- 验证集 413 张 1066 个实例,单图最多 72 个
- 边界框面积占比中位数:训练集 1.23%,第 10 百分位 0.1486%(约 25×25 像素)

## 2. ⚠️ 发现一处数字对不上:"最大可达约 14%"

`03-model-analysis.tex` 第 10 行原句:"……第 10 百分位仅约 0.15%(约
25×25 像素),**最大可达约 14%**,尺度差异大。"

重新统计训练集边界框面积占比(`fig_data_scale.py` 输出):

| 统计量 | 数值 |
|---|---|
| 中位数 | 1.2305% |
| p10 | 0.1486% |
| **p90** | **14.2017%** |
| **真实最大值** | **99.6878%**(近乎整幅画面) |
| 面积>20% 的实例数 | 541 / 8038(6.73%) |
| 其中类别分布 | Dent 477 / Hole 25 / Rusty 39 |

**真实最大值是 99.7%,不是 14%。但第 90 百分位(14.20%)跟文字写的"约 14%"
几乎精确对上。** 判断:大概率是文字把"第 90 百分位"误写/误记成了"最大值",
而不是数据本身有问题——这类描述性统计通常是先算分位数、后手写成句子,
"90 百分位"→"最大可达约" 这种转述滑移很容易发生。

进一步排查那 541 个 >20% 的实例:并非均匀分布在三类里,而是集中在 Dent
(凹陷,477 个,占比最高),Hole 25 个、Rusty 39 个。Dent 类里有多张不同
图像的框坐标完全相同(`w=h=0.998438`,即几乎覆盖整幅图像),不是随机噪声
的形态,更像是"大范围/弥漫性凹陷"场景下的标注惯例(整块受损表面标一个大框),
不是随机标注错误——但这只是基于坐标分布形态(重复出现同一精确数值)的合理
推测,**没有逐张目视核实**过这些图像,不能排除个别确实是标注异常。

## 3. 建议(不影响代码交付,供论文手/建模手决策)

- `fig_data_scale.py` 生成的图按真实分布画(对数轴,不裁尾),图上标了中位数
  与 p90 两条参考线——p90 会跟文字"14%"对上,但柱状图会诚实地把长尾画出来,
  图文放在一起时这处矛盾会比较显眼。
- 本人(编程手)不改 `paper/*.tex`,这处文字口径需要论文手/建模手确认后自己改。
  两种改法都成立,看想强调哪个事实:
  1. 把"最大可达约 14%"改成"第 90 百分位约 14%,个别弥漫性凹陷标注可达
     整幅画面"(如实反映长尾,呼应图里能看到的分布形态);
  2. 或者认为 541 个大框是标注质量问题,单独核实/清洗后再定论(工作量较大,
     且没有证据支持这是错误标注,不建议在截稿前临时做)。
- 个人倾向 1(如实改措辞),因为坐标形态更像标注惯例而非错误,且现在改动
  一句话成本最低。
